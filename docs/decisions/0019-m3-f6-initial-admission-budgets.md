# ADR-0019 — Initial M3 per-source resource admission budgets

Status: implementation decision pending PR review. Date: 2026-10-15.

M3 local processing must refuse excessive work before hashing/parsing where the source-byte length is known, before retaining unbounded parser output, and before expensive target canonicalization/GEOS operations. It must not truncate input or return a trusted partial graph. Existing M2 domain semantics remain unchanged for admitted evidence.

This batch applies the documented default budgets: 64 MiB original source bytes (the existing explicitly configurable hard ceiling remains 256 MiB), 200,000 FIT record frames/GPX track points, 10,000 continuity parts, 20,000 Polygon/MultiPolygon vertices and 250,000 aggregate source/target/M2D coordinate vertices. Stable refusal codes are `SOURCE_BYTES_LIMIT_EXCEEDED`, `OBSERVATION_LIMIT_EXCEEDED`, `PART_OR_INTERVAL_LIMIT_EXCEEDED`, `TARGET_COMPLEXITY_LIMIT_EXCEEDED`, and `OUTPUT_LIMIT_EXCEEDED`. Lower test/caller limits for byte, observation and part inputs are validated against their hard ceilings; M3 persistent processing currently uses the defaults. Target and output ceilings are fixed at their defaults in this batch.

Byte rejection happens before digest computation. FIT records and GPX points/segments are counted during parser iteration, and parsing stops when the next item would exceed the limit. FIT record count is used as a conservative work bound even when a record has no position. The follow-up GPX parser performs a streaming well-formedness preflight and streaming XSD validation, clearing completed XML nodes before counting/canonicalizing points; it no longer retains the complete XML tree. A large current XML subtree remains bounded by the admitted source-byte limit, and process-isolated RSS enforcement is not yet available. Target coordinate nesting is counted iteratively before canonical serialization, JSON Schema/GEOS processing and graph identity construction. Derived/exported budget counts raw source coordinates, target vertices and all M2D segment vertices before M2E export. A refusal raises before graph insertion; task lifecycle records a failed attempt and keeps the admitted raw source available for explicit retry.

Parser and package bytes are included in the existing execution artifact fingerprints, so a graph produced under another implementation cannot be silently replayed as if it used these limits. Admission policies do not round, simplify, truncate or invent route coordinates.

This was the initial partial F6 implementation. Follow-up ADR-0021 adds the formal M2B quality-fragmentation default/hard cap and independent verifier guard. Configurable task profiles, larger target/output ceilings, one-pass/indexed geometry algorithms, wall-clock and RSS worker enforcement, complete persistence rollback acceptance, and independent producer/verifier 200/400/800/1600 benchmarks remain open. This ADR does not claim F6 complete, M3 accepted, or M3 DONE.

# Post-M2 audit follow-ups F3–F6 — owned work and executable acceptance gates

**Status:** ACTION CONTRACT / partial implementation started. **M2 is DONE with documented limitations; M3 is IN PROGRESS.** Shared strict JSON admission is implemented as the first prerequisite; basic source/M2A storage and replay are implemented; basic graph replay is also implemented; full runtime, enhanced custody and remaining F6 gates remain open. This document converts the independent Codex audit's F3–F6 observations from prose into owned engineering obligations. None of these items authorizes retroactive changes to the accepted M0/M1 contract or silent changes to M2 quality/spatial policy.

**Source audit:** independent Codex full-repository review of `7059953c` (report provided by the project owner); corrective F1/F2 PR #18 and [post-Codex M2 re-exit](milestone2-codex-reexit-review.md). The F3/F4 limitations are accepted **as limitations**, not proven harmless for every physical activity. F5/F6 are **open engineering tasks**, not completed by the M2 re-exit.

## Issue #22 local file-entry limit (implemented separately)

`ingest_file` enforces the source-byte row below for local regular files: 64 MiB default, configurable through 256 MiB, bounded descriptor reads, no parsing/hash on excess, and explicit rejection of non-regular descriptors. The initial F6 batch extends byte admission to `ingest_bytes`, counts FIT records/GPX track points and parts while iterating, checks Polygon/MultiPolygon vertices before canonical JSON serialization or GEOS conversion, and caps M2D/export vertices before M2E export. The M3 task path uses default observation, part, and quality-fragmentation limits; low-level ingestion and quality APIs accept validated overrides up to documented hard ceilings. Target/output ceilings remain fixed at defaults. GPX parsing uses a streaming well-formedness preflight and schema-validating `iterparse`; M2B now caps aggregate intervals, diagnostics, gaps, nested source references, and constraints at 10,000 by default. The independent verifier rejects over-ceiling claims before constructing edge maps. Over-budget M2B evidence is persisted as a failed stage with no M2C–M2F proof result. These checks bound retained structures, not process RSS or CPU. No process-level time/RSS watchdog or scaling benchmark acceptance is claimed. See [M2A entry contract](milestone2a-canonical-ingestion.md). Scalable/indexed algorithms, strict over-budget rollback across task persistence, configurable profiles, process time/RSS guards and performance evidence remain open.

The streaming parser change is recorded in [ADR-0020](decisions/0020-m3-f6-streaming-gpx-parser.md); it reduces XML-tree retention but does not claim the F6 process RSS/time gate. Quality-fragment admission and fail-closed M2B behavior are recorded in [ADR-0021](decisions/0021-m3-f6-quality-fragment-budget.md).

## F6 numeric performance and resource-budget contract (remaining implementation pending)

The implementation enforces default byte/observation/part/target/output bounds; configurable ceilings and process-level time/RSS guards remain open. ### Baseline reproducible performance profile (ADR-0013)

The former exact-hardware-only exit gate is superseded by [ADR-0013](decisions/0013-m3-layered-persistence-and-custody.md); see [historical protocol](history/post-m2-fixed-runner-action-contract.md). All seven default/hard budget rows above remain mandatory and unchanged. Baseline correctness and resource limits cannot be waived for a faster machine.

Before measurements freeze and save CPU/vCPU model, OS/kernel, allotted cores/affinity and quotas, Python/dependency/native artifact hashes, generator seed and benchmark code commit. Use an isolated single worker with no concurrent benchmark/build workload; a reproducible VM/container is permitted. Compare baseline and candidate in the **same** frozen environment. Changed environment is NOT_COMPARABLE and requires a new declared baseline with both runs; never overwrite old failures or select a new environment solely to hide regressions.

For each producer and independent verifier separately: 200/400/800/1600 fragmented parts, 2 warm-ups and 7 measured repetitions per size, median; repeat 3 clean runs. Both 400→800 and 800→1600 ratios must be **≤2.8** in each run. For timers below 20 ms, freeze identical batched repetition counts per size before candidate measurement and normalize per invocation; report raw batch durations to avoid noise-based ratio claims. Publish absolute medians and peak RSS. At 1600 parts each function median must stay within the 90 s default activity wall-clock cap and worker RSS within 1 GiB; complete end-to-end work must also satisfy the same default caps. This coarse safety ceiling is not a low-latency claim. Scaling and budget checks must all pass; an unavailable/unstable environment yields NOT_TESTED, not PASS.

Test every default and hard ceiling at/immediately above admission, including source bytes, observations, parts/intervals, target/output vertices, time and memory. Refuse before unbounded work, avoid silent truncation and publish no partial verified graph. Once raw admission is durably committed, a later processing failure retains that evidence with an explicit resumable/terminal result. Basic mode checks transactional graph publication; enhanced mode additionally checks signed finality boundaries.

### Optional named performance claim: i7-8700 reference profile

The original dedicated i7-8700/two physical cores/Ubuntu 24.04.1 profile and attested OCI/software setup remains necessary **only** to advertise the original **≤1.0 s / 512 MiB** at 1600 fragments claim. The complete setup is preserved in the historical protocol linked above and adopted for this named claim. Ratios ≤2.8, 2 warm-ups + 7 measurements and 3 passing clean runs still apply. No matching runner means this named claim is NOT_TESTED; it does not block baseline M3 acceptance or imply generic hardware equivalence.

## Required scheduling and decision boundaries

1. **Now (before tables/cache implementation):** adopt ADR-0013 and version the [M3 evidence-custody / reload contract](milestone3-evidence-custody-contract.md); record F3 and F4 as *explicit uncertain evidence semantics* in persisted snapshot metadata, never as an unstated assumption. Identify the JSON admission and resource-budget design; no implementation claims.
2. **M3 earliest work:** implement immutable raw custody and verified re-ingestion/derivation first; implement F5 unified strict JSON admission **before** persisted JSON is treated as trusted; implement F6 admission budgets before unbounded imports / concurrent batch jobs are enabled.
3. **M3 exit:** demonstrate exact raw → derived snapshot chain and replay tests, F5 rejection parity, F6 bounded behavior/benchmark evidence. A green M2 unittest suite or successful SQLite writes alone do not satisfy the gate.
4. **M5 / later quality algorithm decision:** choose deliberately whether optional FIT timer events or sparse-interval heuristics justify new quality uncertainty. Such a policy requires independent evidence, named configuration, version bump, provenance retention, false-positive/false-negative tests and a non-fabrication proof. **Do not** classify all timer pauses as GPS gaps by default.
5. **Future temporal aggregates:** reuse `duration_basis` and original-parent screening status; do not label proportionally allocated region dwell time as observed. Any such aggregate requires an explicit algorithm/uncertainty contract and source-level replay witnesses.

## Audit test vectors that must remain reproducible

- **F3:** FIT positioned points on either side of a one-hour `timer stop_all/start` hiatus while the chord crosses TargetArea; characterize **current** behavior and only change it under an explicitly versioned future policy. `complete` is always relative to available accepted geometry, never an attestation of actual route completeness.
- **F4:** high-latitude edge `(-89,80) → (89,80)` over 86,400 s, clipped to [-1,1] longitude, parent cap 30 m/s. Check original-parent pass and fragment-speed divergence; neither is allowed to imply a measured intermediate crossing time.
- **F5:** `{"position":[1e-400,0]}` must never be silently normalized to `[0.0,0]` by a supposed strict loader; `{"relation":"inside","relation":"outside"}` must never be silently last-write-wins in either test or runtime admission.
- **F6:** 200/400/800/1600 fragmented parts show the old quadratic baseline; the replacement **must pass the 2-warmup/7-run median ≤2.8 scaling and baseline budget gates** for both producer and verifier; ≤1.0s/512MiB is a separately measured optional named claim, and the seven explicit default/hard resource budgets above, while preserving maximality, parent lineage and exact immutable snapshot checks.

## Non-conflation

- Documented ≠ fixed: F3 is an acknowledged *coverage limit*, not proven true-route coverage; F4 is a *derivation assumption*, not observed telemetry.
- Design accepted ≠ implementation completed: F5/F6 and M3 custody cannot become DONE via document merges.
- CI green ≠ universal input/device compatibility: vendor FIT profiles, Android/iOS browsers, real-world input validity and adversarial resource exhaustion require separately scoped evidence.
- F7/M3 custody is **mandatory** and separately specified in [M3 evidence-custody contract](milestone3-evidence-custody-contract.md); neither `sha256` stored next to a mutable JSON object nor a self-consistent re-hash is sufficient.

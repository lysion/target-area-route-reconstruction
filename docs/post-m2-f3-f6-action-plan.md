## F6 numeric performance and resource-budget contract (implementation pending)

These are **proposed M3 v0.2 gate thresholds chosen for a conservative local single-activity runtime**, not observed performance results or evidence of scalable current M2. Before enabling large historical batch imports, measure, justify and version any approved limit change in a new review; do not quietly relax these bounds to make CI green.

| Resource | Default per-source budget | Maximum configurable ceiling | Over-limit result |
|---|---:|---:|---|
| Original FIT/GPX byte length | 64 MiB | 256 MiB | `SOURCE_BYTES_LIMIT_EXCEEDED` |
| Positioned observations | 200,000 | 1,000,000 | `OBSERVATION_LIMIT_EXCEEDED` |
| Continuity parts / quality fragmentation | 10,000 | 100,000 | `PART_OR_INTERVAL_LIMIT_EXCEEDED` |
| Target polygon vertices (all rings/components) | 20,000 | 100,000 | `TARGET_COMPLEXITY_LIMIT_EXCEEDED` |
| Derived/exported coordinate vertices | 250,000 | 1,000,000 | `OUTPUT_LIMIT_EXCEEDED` |
| End-to-end per-Activity wall clock | 90 seconds | 300 seconds | `PROCESSING_TIME_LIMIT_EXCEEDED` |
| Worker peak resident memory (RSS) | 1 GiB | 2 GiB | `MEMORY_LIMIT_EXCEEDED` |

**CI benchmark protocol:** pin Ubuntu runner image, Python 3.11, GeographicLib, Shapely and **actual GEOS native binary digests**; publish runner specs, workload generator seed/source digest and raw measurements. Isolate the M2D producer and independent verifier to expose either quadratic scan. Execute 2 warm-ups, then 7 measured invocations for each of 200/400/800/1600 fragmentation sizes in fresh repeatable processes; use the median wall time. Pass only if both 400→800 and 800→1600 median ratios are **≤2.8 for EACH function**, each 1600-part median **≤1.0s**, and process peak RSS **≤512 MiB** for this fixture. Require the final observed geometry/parent lineage and maximality results to remain unchanged. If runner/image changes, rebaseline explicitly with reviewed diffs; do not silently redefine passing.

**Budget enforcement evidence:** test exactly at and immediately above each default/ceiling, oversized raw source before eager allocation, huge nested geometry, high-output clipping and a timeout/kill during persistence. Units are binary MiB/GiB. The hard ceiling cannot be exceeded by a normal caller setting; the M3 gate must prove limits are enforced *before* unbounded work and that no partial `verified` graph/GraphCommit is published. Budget failure must preserve already admitted immutable raw evidence where custody committed, with explicit structured error and resumable/terminal distinction.

## Required scheduling and decision boundaries

1. **Now (before any M3 persistence implementation):** accept and version the [M3 evidence-custody / reload contract](milestone3-evidence-custody-contract.md); record F3 and F4 as *explicit uncertain evidence semantics* in persisted snapshot metadata, never as an unstated assumption. Identify the JSON admission and resource-budget design; no implementation claims.
2. **M3 earliest work:** implement immutable raw custody and verified re-ingestion/derivation first; implement F5 unified strict JSON admission **before** persisted JSON is treated as trusted; implement F6 admission budgets before unbounded imports / concurrent batch jobs are enabled.
3. **M3 exit:** demonstrate exact raw → derived snapshot chain and replay tests, F5 rejection parity, F6 bounded behavior/benchmark evidence. A green M2 unittest suite or successful SQLite writes alone do not satisfy the gate.
4. **M5 / later quality algorithm decision:** choose deliberately whether optional FIT timer events or sparse-interval heuristics justify new quality uncertainty. Such a policy requires independent evidence, named configuration, version bump, provenance retention, false-positive/false-negative tests and a non-fabrication proof. **Do not** classify all timer pauses as GPS gaps by default.
5. **Future temporal aggregates:** reuse `duration_basis` and original-parent screening status; do not label proportionally allocated region dwell time as observed. Any such aggregate requires an explicit algorithm/uncertainty contract and source-level replay witnesses.

## Audit test vectors that must remain reproducible

- **F3:** FIT positioned points on either side of a one-hour `timer stop_all/start` hiatus while the chord crosses TargetArea; characterize **current** behavior and only change it under an explicitly versioned future policy. `complete` is always relative to available accepted geometry, never an attestation of actual route completeness.
- **F4:** high-latitude edge `(-89,80) → (89,80)` over 86,400 s, clipped to [-1,1] longitude, parent cap 30 m/s. Check original-parent pass and fragment-speed divergence; neither is allowed to imply a measured intermediate crossing time.
- **F5:** `{"position":[1e-400,0]}` must never be silently normalized to `[0.0,0]` by a supposed strict loader; `{"relation":"inside","relation":"outside"}` must never be silently last-write-wins in either test or runtime admission.
- **F6:** 200/400/800/1600 fragmented parts show the old quadratic baseline; the replacement **must pass the numeric 2-warmup/7-run median ≤2.8 doubling-ratio and ≤1.0s/512MiB thresholds** for both producer and verifier, and the seven explicit default/hard resource budgets above, while preserving maximality, parent lineage and exact immutable snapshot checks.

## Non-conflation

- Documented ≠ fixed: F3 is an acknowledged *coverage limit*, not proven true-route coverage; F4 is a *derivation assumption*, not observed telemetry.
- Design accepted ≠ implementation completed: F5/F6 and M3 custody cannot become DONE via document merges.
- CI green ≠ universal input/device compatibility: vendor FIT profiles, Android/iOS browsers, real-world input validity and adversarial resource exhaustion require separately scoped evidence.
- F7/M3 custody is **mandatory** and separately specified in [M3 evidence-custody contract](milestone3-evidence-custody-contract.md); neither `sha256` stored next to a mutable JSON object nor a self-consistent re-hash is sufficient.

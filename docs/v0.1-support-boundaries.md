# v0.1 support boundaries and milestone ownership

This is the current tested boundary, not a claim that v0.1 is released. M2D is DONE after independent PR #8 acceptance and merge. M2E is DONE after final-head CI, adversarial source review and PR #11 merge; The original M2F PR #13 acceptance and [M2 exit PASS](milestone2-exit-review.md) were invalidated by independent Codex F1/F2, then superseded by [PR #18](https://github.com/lysion/target-area-route-reconstruction/pull/18) remediation and a fresh [M2 re-exit PASS_WITH_LIMITATIONS](milestone2-codex-reexit-review.md). This accepts the versioned `QualityAlgorithm 0.1.1` canonical partition and `temporal-overlay 0.1.1` per-original-edge screening. **v0.1.0 has not been tagged or published**.

## Source-format support matrix

| Input | Current behavior / acceptance boundary |
|---|---|
| GPX 1.1 `trk` / `trkseg` | Local packaged XSD validation via pinned lxml; ordered track observations, explicit part boundaries, empty-part diagnostics; multiple tracks remain separate parts |
| GPX timestamps/elevation | Optional; UTC normalization and recorded elevation only; missing/invalid temporal evidence does not itself erase valid spatial evidence |
| GPX routes/waypoints | Rejected with `UNSUPPORTED_GPX_ROUTE_OR_WAYPOINT`; no continuity interpretation invented |
| GPX malformed XML / invalid root, range or version / DTD | Explicit failure; no network/entity expansion and no fallback classification |
| GPX extension telemetry | Preserved in raw evidence; not silently promoted into core observations |
| Single FIT Activity stream | FileId and Record parsing via pinned fitdecode; basic message-stream fixtures and a complete synthetic FileId/Record/Lap/Session/Activity fixture; CRC, sentinels, missing positions and original record order tested |
| FIT missing positioned records | Exact source diagnostic indices and neighbors retained; no chord across missing runs; no-position source produces no CanonicalTrack/assessment |
| FIT recorded telemetry | Supported absolute timestamps, altitude, cumulative distance and source/device speed; enhanced/native field precedence tested. Source-recorded speed is distinct from downstream M2F geometry/time-derived speed |
| FIT timer pauses / long sparse sampling interval | **Not continuity evidence in v0.1.** FIT timer stop/start events are ignored for route-part segmentation, and large timestamp gaps alone do not create a source gap. A sparse Record-to-Record chord can be treated as observed-admitted geometry; `complete` is relative to this declared model, not proof of the true travelled path. No implicit time-gap threshold is enabled |
| Chained FIT files / unsupported file type | Explicitly rejected; not a multi-activity import capability |
| Additional FIT profiles, developer fields, compressed-message combinations | Library decoding does not constitute comprehensive project-level acceptance. These combinations are not advertised as comprehensively supported; expanding support requires fixture/production conformance tests |

The synthetic suite is privacy-safe and reproducible. Historical real-world evidence motivated the domain, but it is not a claim of a committed comprehensive device/vendor test corpus. The CI install and end-to-end checks currently demonstrate Ubuntu Linux with Python **3.11**, not an independently validated OS/Python-version/browser compatibility matrix. The project metadata `0.1.0` identifies the intended package version, not a verified public release. See the [M2A implementation record](milestone2a-canonical-ingestion.md) and [raw baseline](../tests/source-fixtures/README.md).

## Admission versus later work

| Limitation / obligation | Owner and present classification |
|---|---|
| Exact M2A→M2C authority, complete observed M2D coverage, strict JSON, numerical/revision reconciliation, gap uncertainty, verifier/mutation and wheel gates | Required **before M2D acceptance/M2E entry**; repaired, regression-tested and independently accepted in merged PR #8 |
| Source support matrix, wheel runtime dependencies/schema data, explicit quality policy and honest limitations | Cross-cutting M2 release obligations; documented and exercised now; maintain through later checkpoints |
| Useful local short-gap admissible bounds | Unsupported with current independent evidence. Current M2B proof is only the CRS84 domain bound. No local disjoint-bound positive M2D integration witness can honestly be claimed; future proof capability requires its own deterministic evidence/verifier/version review |
| GPS quality beyond caller-owned implied-speed screening | Not certified by `usable`; no implicit human-speed or physiological threshold. Future quality algorithms require explicit policy and evidence |
| Non-assessable or numerically unrepresentable input | Explicit unavailable/failure outcome, no assessment; not a promise to repair arbitrary observations |
| Periodic/geodesic spatial clipping | Not current M2C semantics: CRS84 coordinate-plane linear edges, including 179→-179 through 0. M2B geodesic distance screening is separate |
| GeoJSON/basic interactive map | M2E, **DONE** after independently reviewed and merged PR #11. Exact M2C/M2D authority required for export; offline vector map with explicit gap endpoints, no inferred geometry; 3 installed-wheel FIT/GPX→M2E smoke cases |
| Segment speed/pace and coloring | M2F **REOPENED (Codex F2)**: source M2B parent-edge screening result was lost in the original 0.1.0 overlay; 0.1.1 remediation records exact `passed / indeterminate / unavailable / not_screened` plus diagnostic reason. Only explicitly passed **parent edges** render blue solid; numeric indeterminate blue short-dashed; policy disabled blue long-dashed; invalid metrics neutral gray dashed. Clipped time is proportionally allocated, **not** observed at inferred boundary vertices; clip speed can exceed admitted parent-edge cap. F2 fix passed exact-head Codex review with no major findings, installed-wheel attacks and merged-main CI [37847574877](https://github.com/lysion/target-area-route-reconstruction/actions/runs/37847574877). |
| Persistence, durable identity uniqueness and resume/idempotency | M3; current APIs are deterministic local/in-memory operations. Current TargetSegment IDs include the whole assessment seed and can change across assessment revisions; stable cross-revision segment reconciliation needs a separate identity design, not geometry similarity |
| Skill orchestration, platform adapters/acquisition/quota | M4/M5/M6; not part of M2D |
| Cross-Activity route inference, historical route networks, missing-route reconstruction | M7; no inferred centerline, nearest-road path or historical-route guess is emitted now |

The earlier M2A–M2F/exit green CI was insufficient and **reopened by F1/F2**; the corrected contracts were independently re-reviewed and **fresh exit accepted**. This does not imply the longer-term multi-Activity historical reconstruction goal, M3 persistence, M4 skill packaging, real-world device conformance, or publication of `v0.1.0`. The remaining limitations above are not concealed by a green test count.

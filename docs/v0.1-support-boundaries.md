# v0.1 support boundaries and milestone ownership

This is the current tested boundary, not a released v0.1 artifact. **M2 is DONE — PASS_WITH_LIMITATIONS** under the [final exit audit](milestone2-final-exit-audit.md) of `82e62b5`. F1/F2, R2/R3 numerical/identity and native snapshot-codec blockers were corrected in PR #18/#21 and independently exercised against source and a noneditable wheel. Quality/spatial algorithms are 0.1.3 and temporal-overlay is 0.1.1. Earlier PASS and reopening records remain historical; **v0.1.0 has not been tagged or published**. M3 is IN PROGRESS; [strict JSON foundation](milestone3-progress.md) is implemented, basic source/M2A storage and replay are implemented; full graph and enhanced custody remain unavailable.

## Source-format support matrix

| Input | Current behavior / acceptance boundary |
|---|---|
| GPX 1.1 `trk` / `trkseg` | Local packaged XSD validation via pinned lxml; ordered track observations, explicit part boundaries, empty-part diagnostics; multiple tracks remain separate parts |
| GPX timestamps/elevation | Optional; UTC normalization and recorded elevation only; missing/invalid temporal evidence does not itself erase valid spatial evidence |
| GPX routes/waypoints | Rejected with `UNSUPPORTED_GPX_ROUTE_OR_WAYPOINT`; no continuity interpretation invented |
| GPX malformed XML / invalid root, range or version / DTD | Explicit failure; no network/entity expansion and no fallback classification |
| GPX extension telemetry | Preserved in raw evidence; not silently promoted into core observations |
| Single FIT Activity stream | FileId and Record parsing via pinned fitdecode; basic message-stream fixtures and a complete synthetic FileId/Record/Lap/Session/Activity fixture; CRC, sentinels, missing positions and original record order tested |
| FIT missing positioned records | Exact source diagnostic indices and neighbors retained; no chord across missing runs; no-position source produces no CanonicalTrack/assessment |
| FIT recorded telemetry | Supported absolute timestamps, altitude, cumulative distance and source/device speed; enhanced/native field precedence tested. Source-recorded speed is distinct from downstream M2F geometry/time-derived speed |
| FIT timer pauses / long sparse sampling interval | **Not continuity evidence in v0.1.** FIT timer stop/start events are ignored for route-part segmentation, and large timestamp gaps alone do not create a source gap. A sparse Record-to-Record chord can be treated as observed-admitted geometry; `complete` is relative to this declared model, not proof of the true travelled path. No implicit time-gap threshold is enabled |
| Chained FIT files / unsupported file type | Explicitly rejected; not a multi-activity import capability |
| Additional FIT profiles, developer fields, compressed-message combinations | Library decoding does not constitute comprehensive project-level acceptance. These combinations are not advertised as comprehensively supported; expanding support requires fixture/production conformance tests |

The synthetic suite is privacy-safe and reproducible. Historical real-world evidence motivated the domain, but it is not a claim of a committed comprehensive device/vendor test corpus. The CI install and end-to-end checks currently demonstrate Ubuntu Linux with Python **3.11**, not an independently validated OS/Python-version/browser compatibility matrix. The project metadata `0.1.0` identifies the intended package version, not a verified public release. See the [M2A implementation record](milestone2a-canonical-ingestion.md) and [raw baseline](../tests/source-fixtures/README.md).

## Required post-M2 audit follow-ups (not new M2 release claims)

The independent Codex F3–F6 findings have **named owners, concrete test vectors and mandatory evidence gates**, not only informal caveats. See [F3–F6 action plan](post-m2-f3-f6-action-plan.md) and the [M3 immutable evidence-custody/reload contract](milestone3-evidence-custody-contract.md).

| Finding | Current bounded capability | Future required gate / owner |
|---|---|---|
| F3 — FIT timer pause / sparse observations | **Known v0.1 continuity limitation**; timer stop/start is not an inferred gap and `complete` does not authenticate actual traveled route | M3 preserves source bytes, parse identity and limitation on reload; a new **explicit, versioned** event/time-gap quality policy may be designed at M5 or separate M2B extension only with non-fabrication tests |
| F4 — derived clipped time and screen scope | M2F 0.1.1 discloses `duration_basis`, proportional allocation and parent-edge speed screening, not observed crossing time | M3 **must persist and reproduce exact method, policy, screening reason, source parent edge and null status**; high-latitude cap-divergence test required |
| F5 — raw JSON strictness mismatch | **LEXICAL PARITY IMPLEMENTED**; fixture script and runtime share strict rejection; persistence integration remains OPEN | **M3 persistent JSON admission gate:** unify strict duplicate/nonfinite/underflow/Unicode rules with independent negative fixtures; never silently coerce to a valid coordinate |
| F6 — fragmented-path quadratic scans / absent budgets | **OPEN**; no high-volume performance or resource guarantee | **M3 batch-readiness gate:** index/single-pass scanning, reproducible 200/400/800/1600 scaling benchmark (fixed-hardware absolute claims separate), explicit source/point/polygon/output/time/memory budgets and clean limit failures |
| F7 — mutable self-consistent provenance | M2 only verifies a trusted supplied in-memory M2A snapshot | **M3 baseline:** trusted-local immutable-by-application raw/source binding, full DAG and verified replay; coherent hostile storage replacement is outside this profile. **Enhanced extension:** separately anchored signatures/checkpoint and co-forgery/rollback rejection; [B/E mapping](milestone3-evidence-custody-contract.md) |

**Design is not delivery:** the strict JSON prerequisite and local file byte limit do **not** mean remaining F6 gates or M3 raw custody, trust anchoring and reload verifier exist.
